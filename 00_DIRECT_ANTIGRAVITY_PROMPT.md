## 1. PRODUCT MISSION

Continuously discover interesting GitHub repositories and turn them into compelling technology-discovery Shorts and long-form videos.

GitHub is the discovery source.
The repository is the raw material.
The story is the product.
The video is the final output.

Initial target:
- 2–3 Shorts/day
- approximately 1 long-form/day when enough valid stories exist
- English-first
- localization-ready architecture for later Vietnamese/other languages
- scheduled autonomous operation
- automatic internal QA
- automatic retry/repair
- fail-closed publishing

Never manufacture a story merely to satisfy a quota.

## 5. CONTENT-FIRST PHILOSOPHY

This is a content factory, not merely a repository-review catalog.

Do not optimize only for technical quality.

Track separately:
- total stars
- star momentum where measurable
- forks
- contributors
- commits
- releases
- recent activity
- novelty
- visual potential
- curiosity
- explanation simplicity
- story potential
- audience relevance
- content diversity

TOTAL STARS != CURRENT MOMENTUM != TECHNICAL QUALITY != CONTENT POTENTIAL.

A technically imperfect or difficult project can still be excellent content if it has an unusual capability, surprising concept, strong visual potential, strong curiosity, trend relevance, or an easy-to-explain story.

Do not fabricate or exaggerate capabilities.

## 6. STORY FORMATS

Support:
- single repository story
- 2–3 repository comparison
- 4–6 repository list
- category/trend story
- long-form deep dive

Repository count is dynamic.

RULE:
STORY DETERMINES REPOSITORY COUNT.

Do not force every Short to contain 5–6 repositories. Do not dilute a very strong single-repository story.

## 7. HOOK/NARRATIVE

Generate multiple hook candidates and select using evidence, curiosity and clarity.

Avoid generic openings.

Narrative should answer:
1. What is it?
2. Why are people paying attention?
3. What is unusual?
4. Why might viewers care?
5. What should they remember?

Do not simply paraphrase README text.

Desired transformation:
repository → evidence → interesting capability → story angle → hook → narrative → visual explanation → video

## 8. FACT VERIFICATION

Distinguish:
- VERIFIED FACT
- DOCUMENTATION CLAIM
- COMMUNITY SIGNAL
- MODEL INFERENCE
- EDITORIAL INTERPRETATION

Important claims require evidence references.

Conflicts must be recorded and resolved where possible. Otherwise lower confidence or block publication.

## 9. INTERNAL QA

QA is continuous:
Discovery QA
Research QA
Scoring QA
Story QA
Fact QA
Script QA
Visual QA
Voice QA
Audio QA
Render QA
Final Red-Team QA

When QA fails:
1. identify the failing component;
2. attempt automatic correction;
3. regenerate only the affected artifact;
4. re-run QA;
5. retry within limits;
6. quarantine/escalate only after recovery fails.

Do not restart the entire pipeline unnecessarily.

## 10. FAIL-CLOSED PUBLISHING

Any mandatory gate returning FAIL, UNKNOWN, MISSING, UNRESOLVED, EXPIRED or CONFLICT means NO PUBLISH.

Mandatory gates:
- valid video
- valid metadata
- fact verification
- script QA
- visual QA
- audio QA
- render QA
- final red-team
- duplicate check
- authentication
- publishing configuration

Never bypass QA because of schedule pressure.

## 11. RETRY/RECOVERY

Implement configurable retry counts and exponential backoff for transient network errors.

For generation failures, repair/regenerate the affected artifact and retest.

Never retry indefinitely.

## 12. CONTENT DIVERSITY

Track previously used:
- repositories
- topics
- categories
- narrative angles
- hook patterns
- technology families

Avoid repetitive consecutive videos when sufficient alternatives exist.

## 13. VISUAL PRODUCTION

Visuals should explain technology.

Possible sources:
- official repository UI/screenshots where permitted
- documentation
- code
- terminal demos
- architecture diagrams
- generated conceptual visuals

Clearly distinguish generated/conceptual visuals from real evidence. Never make synthetic visuals look like authentic screenshots or experimental data.

## 14. VOICE

English-only initially.

Prioritize:
- natural human-like prosody
- clear pronunciation
- conversational delivery
- suitable pacing
- broadcast-quality intelligibility

Voice QA must check pronunciation, pacing, timing, clipping, silence anomalies and synthetic artifacts.

## 15. VIDEO

Shorts default:
- 1080x1920
- 9:16
- approximately 20–60 seconds

Long-form default:
- 16:9

Validate duration, resolution, codec, frame rate, audio, subtitles, decode integrity and mobile readability.

## 16. SCHEDULED AUTOPILOT

Support configurable cron/scheduler triggers.

A scheduled trigger authorizes the configured autonomous workflow.

No conversational APPROVE & CLOSE is required in normal scheduled mode.

## 17. PUBLISHING

After all mandatory QA passes:

READY_FOR_PUBLISH
→ Publisher
→ upload
→ verify response
→ verify video ID/status
→ record publication artifact

Never expose credentials or tokens.
